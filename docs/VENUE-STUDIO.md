# Venue Studio

The organizer's seating map page (`/organizer/events/[id]/map`), extended into
five workspaces, and the buyer's seat picker, extended to three views. Built
2026-11-09.

## What it is

| Workspace | What the organizer does | Stored in |
|---|---|---|
| **Venue** | Name, kind of venue, standing capacity, accessibility, notes for buyers, a venue photo, **venue size** (ballroom to stadium) | `layout.venue`, `layout.world` |
| **Layout** | The existing 2D editor, plus **Seating section** (rows × seats in one step, straight or fanned toward the stage, up to 24 sections around the stage at once) and five new area kinds (video screen, standing area, walkway, accessible seating, barrier) | `tables` (rows are stock), `layout.sections`, `layout.zones` |
| **3D** | The room built from the 2D layout: rake, stage height, lighting (concert / gala / daylight), screens, enclosure. Tap a seat to sit in it | `layout.scene` |
| **360°** | Every seat has a generated view. Upload real 360° photos and link them to rows | `layout.views` |
| **Preview** | The buyer's own component on the draft, with today's availability. **Seat holds** blocks/releases seats | `seats.status` (`blocked`) |

Buyers get **2D · 3D · 360°** on `/e/[slug]/seats`, over one selection: a seat
picked in any view is in the same basket, under the same per-order limit, and
the hold and checkout do not know which view it came from. A venue card under
the map shows the Venue workspace's details.

## Design rules

- **No new stock model.** A section is rows (`tables` of shape `row`, ≤60
  seats) plus a name in `layout.sections`. Seats are still generated by
  `save_venue_map`. No migration.
- **3D is derived, never authored.** `components/venue/sceneModel.js` lifts the
  2D geometry (`seatingGeometry.js`) into metres (one seat pitch = 0.55 m).
  Row height follows from distance to the stage and one rake angle, so moving a
  section in 2D re-tiers the stands. Pure and unit-tested.
- **One renderer for 3D and 360°.** `VenueScene3D.jsx` flies the camera from the
  orbit view into the seat. three.js (pinned `0.186.1`) is imported inside an
  effect, so pages that never open 3D never download it.
- **The client sends image paths, never URLs.** `backend/services/venueStudio.js`
  keeps only paths this event's upload step could have created
  (`events/<id>/venue-…`, `…/panorama-…`) and computes each URL on save. It
  also clamps the studio's keys and caps the layout blob at 256 KB.
- **Blocking only moves `available` ⇄ `blocked`.** Held and sold seats are left
  alone and reported as unchanged (`PUT /events/:id/venue-map/availability`,
  150 seats per call). Every hold path already refuses non-available seats.

## API additions

| Route | Purpose |
|---|---|
| `POST /events/:id/venue-map/upload` | Sign an upload (`kind`: `venue` or `panorama`) |
| `POST /events/:id/venue-map/assets` | Confirm the object landed; returns `{ path, url }` |
| `PUT /events/:id/venue-map/availability` | `{ seatIds, blocked }` → `{ changed, unchanged }` |

## Venue size (per-map worlds)

Positions are percentages of the map's **world**, and the world is per map:
`layout.world = { width, height }` in units, read only through
`seatingGeometry.worldOf(layout)`. Seats keep their size in units (one pitch is
0.55 m, `METRES_PER_UNIT`), so a bigger world is a bigger room, not bigger seats.

| | World (units) | Metres | Fits |
|---|---|---|---|
| Default (every older map) | 1000 × 700 | 22.9 × 16 | ballroom, theatre |
| Hall preset | 2000 × 1400 | 45.8 × 32.1 | concert hall |
| Arena preset | 4000 × 2800 | 91.7 × 64.2 | arena |
| Stadium preset | 8000 × 5600 | 183.3 × 128.3 | stadium bowl |
| Maximum | 10000 × 10000 | 229.2 × 229.2 | |

- **Old maps are unchanged.** A layout with no `world`, or with the editor's old
  fixed `{1000, 700}`, resolves to `WORLD` itself; every function's world
  argument defaults to it, and the default-world code paths are unchanged
  (`mapWorld.test.jsx` renders an old map both ways and compares the markup).
- **One reader.** `seatingGeometry.test.js` fails if any file in `src` imports
  `WORLD`; each consumer takes `worldOf(layout)` and passes it on (editor, buyer
  map, door sales, print pack, 3D model, section builder, Seating Designer).
- **Resizing keeps the room.** The Venue workspace's **Venue size** card
  (presets or metres, applied on a button) calls `useMapDraft.resizeWorld`, which
  moves every table and zone with `moveToWorld`: same spacing in units, centred
  in the new floor, one undo step. It refuses a size the drawn content will not fit.
- **The API clamps it.** `venueStudio.sanitizeLayout` keeps `world` as whole
  units between the default and the maximum, and drops an unreadable one.
  Positions stay `NUMERIC(6,3)` percentages, so no migration: 0.001 % of the
  maximum world is a tenth of a unit.
- **Steps are in units.** Arrow nudges, Ctrl+D offsets and Add-dialog spacing
  are defined in units, so they are the same distance in every venue, and the
  deepest zoom stops at ten seats across rather than a 24th of the content.
- **A bowl in one step.** In a fanned section, *Sections around the stage* (1–24)
  and *Between sections* build a ring of sections named B1, B2…; the angle
  runs ±180° and the distance from the stage reaches half the venue. Rows whose
  centre falls outside the venue are refused with a message. Twelve sections of
  20 rows (24 seats, +1 a row) are 8,040 seats in 240 rows, within the 400-row
  ceiling.

## Known limits

- **Map size is capped by stock, not space.** 400 rows of at most 60 seats
  (24,000 seats) per map. The editor and buyer map draw every seat as SVG; a
  stadium of several thousand seats is drawn, but culling is editor-only.
- **Uploads need storage.** The local stack has storage disabled, so uploads
  answer `STORAGE_NOT_CONFIGURED` there; the viewer was verified with a locally
  served test panorama.
- Replaced or removed studio images are not deleted from the bucket.
- A blocked seat counts as "booked" when removing its row in the editor;
  release it first.
