# Venue Studio

The organizer's seating map page (`/organizer/events/[id]/map`), extended into
five workspaces, and the buyer's seat picker, extended to three views. Built
2026-11-09.

## What it is

| Workspace | What the organizer does | Stored in |
|---|---|---|
| **Venue** | Name, kind of venue, standing capacity, accessibility, notes for buyers, a venue photo, **venue size** (ballroom to stadium) | `layout.venue`, `layout.world` |
| **Layout** | The existing 2D editor, plus **Seating section** (rows × seats in one step, straight or fanned toward the stage, up to 24 sections around the stage at once) and five new area kinds (video screen, standing area, walkway, accessible seating, barrier) | `tables` (rows are stock), `layout.sections`, `layout.zones` |
| **3D** | The room built from the 2D layout: rake, stage height, lighting (concert / gala / daylight), screens, enclosure. Tap a seat to sit in it | `layout.scene` |
| **360°** | Every seat has a generated view. Upload real 360° photos and link them to rows | `layout.views` |
| **Preview** | The buyer's own component on the draft, with today's availability. **Seat holds** blocks/releases seats | `seats.status` (`blocked`) |

Buyers get **2D · 3D · 360°** on `/e/[slug]/seats`, over one selection: a seat
picked in any view is in the same basket, under the same per-order limit, and
the hold and checkout do not know which view it came from. A venue card under
the map shows the Venue workspace's details.

## Design rules

- **No new stock model.** A section is rows (`tables` of shape `row`, ≤60
  seats) plus a name in `layout.sections`. Seats are still generated by
  `save_venue_map`. No migration.
- **3D is derived, never authored.** `components/venue/sceneModel.js` lifts the
  2D geometry (`seatingGeometry.js`) into metres (one seat pitch = 0.55 m).
  Row height follows from distance to the stage and one rake angle, so moving a
  section in 2D re-tiers the stands. Pure and unit-tested.
- **One renderer for 3D and 360°.** `VenueScene3D.jsx` flies the camera from the
  orbit view into the seat. three.js (pinned `0.186.1`) is imported inside an
  effect, so pages that never open 3D never download it.
- **The client sends image paths, never URLs.** `backend/services/venueStudio.js`
  keeps only paths this event's upload step could have created
  (`events/<id>/venue-…`, `…/panorama-…`) and computes each URL on save. It
  also clamps the studio's keys and caps the layout blob at 256 KB.
- **Blocking only moves `available` ⇄ `blocked`.** Held and sold seats are left
  alone and reported as unchanged (`PUT /events/:id/venue-map/availability`,
  150 seats per call). Every hold path already refuses non-available seats.

## API additions

| Route | Purpose |
|---|---|
| `POST /events/:id/venue-map/upload` | Sign an upload (`kind`: `venue` or `panorama`) |
| `POST /events/:id/venue-map/assets` | Confirm the object landed; returns `{ path, url }` |
| `PUT /events/:id/venue-map/availability` | `{ seatIds, blocked }` → `{ changed, unchanged }` |

## Venue size (per-map worlds)

Positions are percentages of the map's **world**, and the world is per map:
`layout.world = { width, height }` in units, read only through
`seatingGeometry.worldOf(layout)`. Seats keep their size in units (one pitch is
0.55 m, `METRES_PER_UNIT`), so a bigger world is a bigger room, not bigger seats.

| | World (units) | Metres | Fits |
|---|---|---|---|
| Default (every older map) | 1000 × 700 | 22.9 × 16 | ballroom, theatre |
| Hall preset | 2000 × 1400 | 45.8 × 32.1 | concert hall |
| Arena preset | 4000 × 2800 | 91.7 × 64.2 | arena |
| Stadium preset | 8000 × 5600 | 183.3 × 128.3 | stadium bowl |
| Maximum | 10000 × 10000 | 229.2 × 229.2 | |

- **Old maps are unchanged.** A layout with no `world`, or with the editor's old
  fixed `{1000, 700}`, resolves to `WORLD` itself; every function's world
  argument defaults to it, and the default-world code paths are unchanged
  (`mapWorld.test.jsx` renders an old map both ways and compares the markup).
- **One reader.** `seatingGeometry.test.js` fails if any file in `src` imports
  `WORLD`; each consumer takes `worldOf(layout)` and passes it on (editor, buyer
  map, door sales, print pack, 3D model, section builder, Seating Designer).
- **Resizing keeps the room.** The Venue workspace's **Venue size** card
  (presets or metres, applied on a button) calls `useMapDraft.resizeWorld`, which
  moves every table and zone with `moveToWorld`: same spacing in units, centred
  in the new floor, one undo step. It refuses a size the drawn content will not fit.
- **The API clamps it.** `venueStudio.sanitizeLayout` keeps `world` as whole
  units between the default and the maximum, and drops an unreadable one.
  Positions stay `NUMERIC(6,3)` percentages, so no migration: 0.001 % of the
  maximum world is a tenth of a unit.
- **Steps are in units.** Arrow nudges, Ctrl+D offsets and Add-dialog spacing
  are defined in units, so they are the same distance in every venue, and the
  deepest zoom stops at ten seats across rather than a 24th of the content.
- **A bowl in one step.** In a fanned section, *Sections around the stage* (1–24)
  and *Between sections* build a ring of sections named B1, B2…; the angle
  runs ±180° and the distance from the stage reaches half the venue. Rows whose
  centre falls outside the venue are refused with a message. Twelve sections of
  20 rows (24 seats, +1 a row) are 8,040 seats in 240 rows, within the 400-row
  ceiling.

## Known limits

- **Map size is capped by stock, not space.** 400 rows of at most 60 seats
  (24,000 seats) per map. The editor and buyer map draw every seat as SVG; a
  stadium of several thousand seats is drawn, but culling is editor-only.
- **Uploads need storage.** The local stack has storage disabled, so uploads
  answer `STORAGE_NOT_CONFIGURED` there; the viewer was verified with a locally
  served test panorama.
- Replaced or removed studio images are not deleted from the bucket.
- A blocked seat counts as "booked" when removing its row in the editor;
  release it first.

- Table styles are keyed by the table's label, lower case (labels are unique
  per map). The public seat map sends only the visible tables' styles
  (`venueStudio.publicLayout`), so a private table's name never leaks.
- The API cleans `tableStyles` and `look` on save; the frontend reads them
  defensively (`mapStyle.js`).
- The printed pack draws the shapes, walls and doors but keeps ink only, never
  the organizer's colours.
- Without the migration, saved looks read as none and saving one says the
  feature is off; everything else works.

**Table size, multi-select and 3D numbers (2026-11-19).**

- *Table size* (50%–150%) is `layout.tableStyles[label].scale`, set in the
  table panel or for a whole selection. The geometry functions stay in
  natural units. Each view applies `seatingGeometry.tableScale` around them:
  an SVG `scale()` on the buyer map, the editor and the print pack, and a
  multiply in `sceneModel`. Framing, culling and box-select use `tableReach`.
  100% is never stored. No migration.
- *Pick several* (key M) is a third canvas tool. Each tap adds a table to the
  selection or removes it, so a tablet doesn't need Ctrl or Shift. The
  multi-select panel sets the ticket type, category and size of every
  selected table as one undo step.
- *Table numbers in 3D*: `roomBuilder` puts a numbered plate over every table
  body, in both the organizer and buyer 3D views. The numbers are hidden in
  the 360° seat view, like the other labels.

## Import from a picture (2026-11-19)

Venue Builder → Add to layout → **Import from a picture**: the organizer uploads
a floor plan or seating chart and AI redraws it as an editable map.

- `POST /ai/events/:eventId/seating-plan/from-image` (`aiController.createSeatingPlanFromImage`)
  reads the picture with the vision models (`services/ai/seatingFromImage.js`):
  every table's box in % of the picture, seats counted per side, the curved side
  of D-shapes, areas, wall segments, doors, floor labels and colours. The answer
  is clamped and checked (`validateMap`); one use of the Seating Designer's
  daily allowance, refused for maps with held or sold seats, never stored.
- `components/seating/imageImport.js` (`planToMap`) places it: the picture is
  scaled so its tables match ours in size, then enlarged only as far as needed
  for no two tables' seats to touch (at most 1.6×). Tall tables turn 90°,
  curves face the way they are drawn, and side counts turn with them.
- The dialog shows the picture and the rebuilt map side by side; Apply puts it
  in the unsaved draft as one undo step. Ticket types are left to assign.
- `test/fixtures/referencePlan.js` is the owner's reference plan written out as
  the AI should read it; `imageImport.test.jsx` checks it rebuilds with every
  table, the right turns and no overlapping seats.

## Settings system (2026-11-21)

The seating map's panels and the vendor floor plan's panel share one set of
controls and one panel shape, in `components/inspector/`:

- `fields.jsx`: every control. Label above for text, numbers and lists; label
  beside for colours, switches, steppers and segmented choices; yes/no is
  always a switch; one-of-a-few is always `Segmented`; hints only where a field
  has a consequence.
- `Inspector.jsx`: head (icon, name, facts), folding sections that remember
  whether they are open (per section id, across selections), and a footer of
  actions pinned to the panel's bottom edge.

| Panel | Sections, in order |
|---|---|
| Table | Table (name, seats, shape, seats per side) · Tickets & price · Private access · Appearance (folded) |
| Area | Details (name, second line, size in metres) · Appearance |
| Selection | Tickets & price (pickers show the shared value or "Mixed") · Appearance |
| Whole map | Pricing ("Select these N" picks the unpriced tables) · Map look · Keyboard shortcuts |
| Floor plan | Whole hall · Tool (Booth / Row options, Finish wall) · Booth · Selection |

Which prices a table offers follows `purchaseMode`: seats only hides the
whole-table price; whole tables only puts it first and hides the seat price.

"Add to layout" is grouped (Seating, Room, Start from) and shown once: the left
column where the editor is 70rem wide, the toolbar's Add menu below that. The
AI designer is a "Start from" item; its banner appears only on an empty map.
The 3D preview always sits under the inspector. Sticky panels stick under the
shell's pinned top, whose height AppShell publishes as `--es-shell-top-h`.

**Second pass (same day).** Three columns from a 60rem editor (a 1440px laptop); below that the Add menu and the Map inspector's "Show on the map" stand in. Zoom floats on the canvas corner in both editors, so each toolbar is one row. Bare keys (Delete, Backspace, arrows, Space, letters) belong to a focused inspector control, not the map; Ctrl/⌘ shortcuts still reach the map, and pressing the canvas hands focus back to it. The editor's shortcuts run only on the Layout tab. `NumberField` keeps its own text: in-bounds values apply while typing, everything else on blur or Enter (`live={false}` for Seats and hall size). Floor plan tools hand back to Select after placing, so the inspector opens on what was placed. A bulk whole-table price is offered where the event sells whole tables.

## Vendor booths on the venue map (2026-11-22)

The owner asked to merge the event's seating map and the vendors' floor plan.
A reserved-seating event now has **one drawing of the hall**: seats and vendor
booths are added, moved and saved in the same venue map editor.

- **Storage stays split.** Seats are `tables`/`seats`; booths stay in
  `vendor_floor_plans.plan`, because offers and bookings point at a booth's id
  (`vendor_applications.booth_key`). A plan drawn on the map carries
  `onSeatMap: true` and is saved in the map's world (plan width/height = world).
  Booths are never written into `layout_json` (`writeZones` skips them,
  `readZones` drops them). No migration.
- **Editor.** Booths ride in the draft as zones of kind `booth`
  (`venueZones.BOOTH_KIND`, `BOOTH_META` 3 x 3 m; not in `ZONES`, so the AI and
  the Add dialog never see them). The booth code is the zone's `label`.
  `components/seating/boothZones.js` converts plan <-> zones. Add to layout has a
  **Vendor booths** group (Booth, Row of booths); `BoothPanel.jsx` is the
  inspector (code, booth type, unavailable, size; a booth a vendor holds names
  them and cannot be deleted); a Selection can set one booth type for many; the
  Layers card gets **Vendor booths**; Select-by-type has "All vendor booths".
- **Save** (`useMapPersistence`): booths first, `PUT /events/:id/vendors/floor-plan`
  (it refuses to drop a held booth, which stops the whole save), then the map.
  Booths are sent only when they changed. A separate plan with booths is offered
  once as **Bring them onto this map** (booths only; its walls and labels stay
  behind).
- **Everyone sees the same hall.** `GET /public/events/:slug/seat-map` returns
  `vendorBooths` (buyers see booths, with vendor names once booked, paid and
  listed). Vendor views (public vendor page, vendor booking, the organizer's
  booth picker) get `venue` = `vendorService.seatMapContext` (world, zones, look,
  tables; private tables only for the organizer) and draw it under the booths
  (`VenueUnderlay.jsx`).
- ~~General admission events have no seat map~~ — superseded 2026-11-23, see
  "The event map" below. Only **listing-only** events keep the standalone floor
  plan editor; the API refuses `onSeatMap` for them.

## Private tables, Unavailable tables and the colour rules (2026-11-24)

**Private tables are visible.** The public seat map returns every table. A private table the buyer has not unlocked comes back with `locked: true`, `canBookWhole: false`, no price and no ticket type, and its seats as unavailable with `reason: 'private'` (`seatMapController.publicMap`). The buyer map draws it marked Private with a lock; pressing the table or any chair opens the password prompt (`SeatPicker` → `UnlockTableDialog`). The unlock token re-fetches the map and the table comes back open. The hold still refuses a private table or seat without the token (`placeHold.js`). `hiddenTableCount` is always 0 now; `lockedTableCount` counts locked ones. The vendor floor plan also shows private tables (`isPrivate`).

**Unavailable tables** (sold or reserved outside Eventsli) are not new stock. Marking one blocks every open seat at it through the Preview's seat-hold mechanism (`useStudioDraft.setTablesUnavailable`), and `save_venue_map`'s `p_availability` saves it in the same transaction as the map. No migration is needed. Seats a buyer holds or bought are skipped. The table inspector has an Availability section, and the multi-select inspector has "Mark N unavailable" and "Make available again". A new table must be saved first.

**Bulk private.** The multi-select inspector sets one password on every selected table, or makes them public again. The API hashes each *distinct* password once and shares the hash, so the 50-password cap counts distinct passwords. A saved table switched to private with no password is now refused by name, in the draft rules and in `saveMap`, instead of failing the `private_needs_password` constraint.

**One colour rule** (`mapStyle.js`, "THE MAP'S COLOUR RULES"). A table is painted its own colour, then its category's colour, then its ticket type's colour (only when the map has more than one type), then the look's colour (`venueModel.tableTint` + `tablePaint`). Every chair at a table is black (`CHAIR`). Selected chairs get a coral ring, unavailable or locked chairs are faded, and a light edge keeps chairs visible on dark floors. Seats in a row (no table body) carry the row's colour. The buyer map, the editor canvas, door sales, the 3D/360 views (`studioColours`, per-table cloth colours in `roomBuilder`) and the attendee app all read this one rule. The public map now sends `categories` (with colours) and each table's `tierId`.

## The stage screen and Showtime (2026-11-25)

The screen over the stage in 3D and 360° is a show, not a still picture. The code is in `components/venue/stage/`.

**Always landscape.** Every screen is 16:9. `screenModel.screenSize` decides every screen's shape and has no portrait answer. The stage screen is the largest 16:9 that fits under the truss, scaled by the organizer's size (60–100%). Side screens are 16:9 too. A `screen` zone drawn tall on the 2D map turns to run along its longer side. Photos are never stretched: the painter crops them to 16:9 around the organizer's focus point.

**What plays** (`scene.screen` in the layout, read by `screenModel.readScreen` and cleaned by `venueStudio.cleanScreen`):

- Slides, in order, up to 12: title, countdown, headliner (photo, name, line above), lineup, photo (with caption), sponsors, message and music visualizer.
- Title, countdown, lineup and sponsors fill themselves from the event. The map API's `screenFeed` (`services/screenFeed.js`) carries the cover, logo, times, zone, venue, `event_schedule` and `event_sponsors`. The same feed rides the organizer's `GET /venue-map`.
- A slide with nothing to show is skipped, never painted empty (`playableSlides`). The settings say why each one is skipped.
- Look: style (Bold, Elegant, Neon), accent colour, transition (fade, slide, cut), seconds per slide, LED pixel finish, screen size and side screens.

**How it paints.** `screenPainter.js` draws on a 2D canvas, and `screenSlides.js` holds one drawer per slide. All screens in the room share that canvas as one texture. VenueScene3D repaints it on a budget: 30 fps on desktop, 6 on a phone at rest, 24 in Showtime, 4 in the editor's small preview and 1 under reduced motion. It does not repaint when the view is scrolled out of sight. What the screen shows is repainted, never rebuilt; only size and side screens rebuild the room. A tap on a screen goes to the next slide.

**Showtime** (`ShowtimeBar`, top left of every 3D/360° view). It starts only from a tap and the camera never moves (map-stays-still). The house lights dim. Beams swing in the screen's colour on every mood, not only concert. The rim, step lights and truss lamps pulse to the bass, and the screen's colour lights the stage through a point light sampled from the picture.

**Music** (`stageSound.js`) comes in three options:

- Eventsli music: four loops (Arena, Lounge, Cinematic, Chill) synthesized in the browser, so there is nothing to license or download. The default matches the lighting.
- The organizer's MP3 or M4A, up to 8 MB.
- None.

The sound is placed at the screen with an HRTF panner, and the listener is the camera. A back seat hears less of the band and more of the room: the reverb is sized to the room and is not distance-faded. A track that fails to play falls back to Eventsli music. Playback pauses in a hidden tab.

**Uploads.** Slide photos are kind `screen` (images). The soundtrack is kind `soundtrack` (`audio/mpeg`, `audio/mp4`; `mediaService.AUDIO_EXTENSION_FOR`, 8 MB). `ownPath` keeps each kind to its own extensions. **Migration `20261221090000`** lets the `event-media` bucket take those two audio types up to 8 MB. Images are still held to 5 MB in `attach`. Until it runs, track uploads fail and everything else works.

Tests: `frontend/test/stageScreen.test.js` (the 16:9 rule through the real room builder, every slide, style and transition painted, the loops, the clock) and `backend/test/stageScreen.test.js` (paths, extensions, clamping, the feed).

**Second pass (2026-11-25, owner: "the sound is very low", "why can I not upload images and videos", "why can I not raise the width of the stage"):**

- Louder sound. The loops get +10 dB of make-up gain, a limiter sits in front of the speakers, the distance fall-off is gentle (`refDistance` ≈ 0.9 × room radius, rolloff 0.45), and the default volume is 85. Showtime has its own volume slider.
- Uploads. "Add photos" (several at once) and "Add a video" at the top of On the screen make one slide per file. New **Video** slide: MP4/WebM up to 40 MB, kind `clip`, played muted and looping, cropped 16:9 around a focus point. New **Event photos** slide: the event page gallery (`event_media` images, `screenFeed.gallery`) as a photo wall. The migration now also allows `video/mp4` and `video/webm`, with the bucket ceiling at 40 MB (images 5 MB, tracks 8 MB, clips 40 MB, each checked in `attach`).
- Width. The screen width is a % of the stage (40–150%, default 80), no longer capped by the truss: the truss rises to clear it. Stage width and depth sliders in the 3D settings edit the stage zone itself (`useMapDraft.updateZone`, one undo step per drag).
- Uploads never work on a local stack: `supabase/config.toml` has `[storage] enabled = false`, so there is no storage container. They work against real storage.
- Video sound (2026-11-25, "the sound of the video does not work"). A video slide is silent outside Showtime, as browsers require for autoplay. In Showtime its own sound plays from the stage: `painter.audibleVideo` is the current slide's element, and `stageSound.video(el)` routes it once through `createMediaElementSource` into a video bus, unmutes it, and ducks the music bus to 15%. It is muted again when the slide leaves or Showtime ends. Each video slide has a "Play its sound" switch (`sound`, default on). "No music" still creates an engine, so a video is heard even then. A media element can join only one audio graph, so replacing the engine also replaces the video elements (`resetVideos`).
- Steady video (2026-11-25, "work then not work then work"). Slides no longer get equal fixed slots. `screenVideos.createRunningOrder` gives each slide its own length: a video holds the screen until its clip ends (capped at 5 min) and starts from the top each time; a video still loading gets two slots; a failed one gets one. Only a single-slide show loops its video. `createVideoShelf` keeps each video element in the page (Chrome pauses a detached muted video), draws the last good frame while it buffers, and calls `play()` only once at a time.
